# ТЗ: Декларативное управление расстановкой при стандартных положениях

## Цель

Упростить задание поведения игроков при стандартных положениях: вместо написания кода в `team_setup`/`player_setup` игрок задаёт только позиции игроков на поле в виде данных.

## Стандартные положения

Система охватывает все стандартные положения:
- Начальный удар (`"kick off"` — покрывает и старт игры, и возобновление после гола)
- Удар от ворот: свой / чужой
- Угловой: свой левый / свой правый / чужой левый / чужой правый
- Ввод из-за боковой: 8 вариантов — своя/чужая половина × левая/правая сторона × свой/чужой ввод

## Тактическое задание игрока (`tactical.toml`)

Для каждого игрока задаются позиции (регионы) для всех стандартных положений. Все поля обязательны. Одно из значений региона — специальное: `on_ball`, означающее «этот игрок идёт к мячу для выполнения стандарта».

## Гарантия согласованности

При загрузке конфигурации движок валидирует: для каждого стандартного положения значение `on_ball` имеет ровно один игрок в команде. Нарушение — ошибка загрузки.

## Исключение кодового механизма

`team_setup` и `player_setup` как механизмы задания поведения при стандартах упраздняются. Поведение при стандартах задаётся исключительно через регионы в `tactical.toml`.

## Результат для игрока

Для настройки стандартных положений игрок работает только с позициями игроков (в будущем — через UI с фишками). Написание кода для стандартов не требуется.

## Предварительный рефакторинг

До начала основной работы необходимо устранить архитектурные нарушения в модели данных.

### Рефакторинг 1. `PlayerTactical` в ядре не должен знать о футболе

Сейчас `PlayerTactical` (`ynwa-core/src/repository.rs`) содержит именованные поля `goal_kick_own_position`, `corner_own_left` и т.д. — это football-специфичные знания в sport-agnostic слое. Они заменяются одним полем `set_piece_positions: HashMap<String, String>`, где ключи и их смысл знает только `ynwa-football`.

### Рефакторинг 2. Объединить `start_position` со стандартами; выделить `play_positions`

`start_position` семантически является стандартным положением (начальный удар) и переносится в `set_piece_positions` под ключами `"kick off"` и `"after goal"`. `attack_position` и `defence_position` — позиции для фазы игры, не связанные со стандартами; они объединяются в отдельный контейнер `play_positions: HashMap<String, String>`. Маркер `"on_ball"` допустим только в `set_piece_positions`.

После этого рефакторинга `PlayerTactical` содержит два однородных контейнера:
- `play_positions` — ключи `"attack"`, `"defence"` (и возможные будущие игровые режимы)
- `set_piece_positions` — ключи для всех стандартных положений, включая начальный удар

### Рефакторинг 3. Разделение позиций и ролей исполнителя в `PlayerDef`

В `PlayerDef` (`ynwa-core/src/game.rs`) добавляется поле `set_piece_roles: HashSet<String>` для хранения стандартов, которые исполняет данный игрок. Это семантически отдельная концепция от `regions` (позиций) и не должна с ними смешиваться. `ynwa-football` при загрузке: значение `"on_ball"` в `set_piece_positions` → ключ попадает в `set_piece_roles`, а не в `regions`.
