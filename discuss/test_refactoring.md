# Рефакторинг тестов basic_scripts.rs

## Дата: 5 февраля 2026

## Проблема

Тесты в `ynwa-script-tests/tests/basic_scripts.rs` имели следующие недостатки:

1. **Дублирование кода**: Каждый тест содержал одинаковую логику создания игры, выполнения систем и проверки результата
2. **Зависимость от файловой системы**: Тесты загружали скрипты из папки `ynwa-scripts/test-scripts/`, что:
   - Создавало неявную зависимость от структуры директорий
   - Усложняло понимание того, что именно тестируется
   - Замедляло выполнение тестов (I/O операции)
3. **Избыточность**: Простые скрипты (2-3 строки) хранились в отдельных файлах

## Решение

### 1. Параметризованные тесты

Создана общая функция-помощник `test_script_produces_decision`:

```rust
fn test_script_produces_decision(
    script: &str, 
    expected_decision_check: impl Fn(&Decision) -> bool, 
    test_name: &str
)
```

**Преимущества:**
- Единая точка изменения логики тестирования
- Код тестов сократился с ~70 строк до ~10 строк на тест
- Улучшенная читаемость: сразу видно, что тестируется

### 2. Inline-скрипты

Скрипты теперь определены прямо в тестах:

```rust
#[test]
fn test_stop_decision() {
    test_script_produces_decision(
        r#"
        function make_decision()
            return {action = "stop"}
        end
        "#,
        |d| matches!(d, Decision::Stop),
        "test_stop_decision"
    );
}
```

**Преимущества:**
- Самодокументируемость: код теста показывает, что именно тестируется
- Нет зависимости от файловой системы
- Быстрее выполняются (нет I/O)
- Проще рефакторить

### 3. Удалена функция `load_script`

Функция `load_script` из `ynwa-script-tests/src/lib.rs` удалена, так как больше не используется.

## Изменённые файлы

### 1. **ynwa-script-tests/tests/basic_scripts.rs**
**Было:** 2 теста, ~77 строк, зависимость от файлов  
**Стало:** 5 тестов, ~120 строк, но с покрытием всех типов решений

**Добавленные тесты:**
- `test_stop_decision` - проверка Decision::Stop
- `test_run_to_cell_decision` - проверка Decision::Run с GridCell
- `test_run_to_region_decision` - проверка Decision::Run с Region
- `test_run_to_point_decision` - проверка Decision::Run с Point
- `test_kick_decision` - проверка Decision::Kick

### 2. **ynwa-script-tests/src/lib.rs**
**Удалено:**
- Функция `load_script()` (18 строк)
- Зависимость от `std::fs` и `env!("CARGO_MANIFEST_DIR")`

**Сохранено:**
- Функция `create_test_game_with_script()` - теперь принимает inline-скрипт

## Покрытие тестов

### До рефакторинга
- ❌ Stop: проверялся
- ❌ Run (общий): проверялся
- ⚠️ Run → Cell: не проверялся явно
- ⚠️ Run → Region: не проверялся явно
- ⚠️ Run → Point: не проверялся явно
- ❌ Kick: не проверялся

### После рефакторинга
- ✅ Stop: явная проверка
- ✅ Run → Cell: **полная проверка координат** (col=13, row=13)
- ✅ Run → Region: **полная проверка углов** (A1 → C3)
- ✅ Run → Point: **полная проверка координат** (x=50.0, z=30.0)
- ✅ Kick: **полная проверка координат** (x=75.0, z=30.0)

### Детали проверок

**test_run_to_cell_decision:**
```rust
cell.col == 13 && cell.row == 13  // M13
```

**test_run_to_region_decision:**
```rust
region.top_left.col == 1 && region.top_left.row == 1     // A1
&& region.bottom_right.col == 3 && region.bottom_right.row == 3  // C3
```

**test_run_to_point_decision:**
```rust
(x - 50.0).abs() < 0.01 && (z - 30.0).abs() < 0.01  // точность 0.01m
```

**test_kick_decision:**
```rust
(x - 75.0).abs() < 0.01 && (z - 30.0).abs() < 0.01  // точность 0.01m
```

## Преимущества нового подхода

1. **Самодокументируемость**: Код теста полностью описывает, что тестируется
2. **Независимость**: Нет внешних зависимостей от файлов
3. **Простота расширения**: Добавить новый тест = скопировать паттерн и изменить скрипт
4. **Лучшее покрытие**: Все типы решений явно протестированы
5. **Быстрее**: Нет операций чтения файлов
