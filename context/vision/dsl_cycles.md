# О чём тут

Документ фиксирует результаты обсуждения о добавлении циклов в будущий DSL игрока. Он не является финальной спецификацией и предназначен для дальнейшего обсуждения и уточнения деталей.

# Проблема: почему отказ от циклов не сработал

Изначально предполагалось обойтись без циклов и контейнеров (см. [dsl.md](dsl.md)), чтобы не усложнять язык для непрограммистов. Однако практика написания тактик на Lua (`team_a`, `team_b`, `team_c`, `team_d`) показала, что без циклов приходится дублировать однотипные проверки для каждого номера игрока и плодить функции под разную арность (`nearest_teammate_number(n1, n2, n3)` vs `(n1, n2, n3, n4)`, `center_back_with_ball`, `pass_to_first_free_ahead`, `nearest_teammate_ahead_number`, `pass_to_free_or_nearest`, `nonforward_with_ball`).

Все проблемные случаи сводились к двум паттернам:
1. **Первый подходящий** (`pass_to_first_free_ahead`, `nonforward_with_ball`) — перебор заданных игроков в порядке приоритета до первого `decision:`.
2. **Ближайший из подходящих** (`center_back_with_ball`, `nearest_teammate_ahead_number`, `nearest_teammate_number`) — перебор с выбором лучшего по расстоянию.

# Почему не подошли промежуточные варианты

- **Обычный цикл по числам с аккумуляторами**: для поиска «ближайшего из подходящих» требует вводить в DSL отсутствующее значение (`nil`/`none` или сентинелы вроде `0` и `math.huge`) и два синхронизированных аккумулятора (`best_number`, `best_distance`).
- **Функции высшего порядка (`for_each` / передача предикатов)**: слишком высокая когнитивная нагрузка для непрограммиста.
- **Агрегирующая конструкция вида `min <выражение>` в цикле**: когнитивно близка к передаче функции-ключа (как `min_by(x -> ...)`).
- **Цикл по абстрактным числам**: порядок сортировки (`order by`) имеет игровой смысл только для игроков, а не для голых чисел.

# Предлагаемое решение: цикл по игрокам с опциональным `order by`

Вместо двух разных механизмов остаётся **один вид цикла** — по явно заданному списку игроков (`player`).

## 1. Базовый цикл (порядок приоритета)

Цикл не имеет `break`/`continue` — досрочный выход возможен **только через `decision:`**. Если ни один игрок не подошёл, выполнение продолжается после блока цикла (никакой `nil` не нужен).

```text
for player in teammates 6, 7, 8
[
    if player free
    [
        decision: pass to player
    ]
]
```

## 2. Цикл с порядком обхода (`order by`)

Поиск «ближайшего/дальнейшего из подходящих» сводится к тому же циклу, если задать порядок обхода списка:

```text
for player in teammates 6, 8, 7, 11
    order by distance to me ascending
[
    if player free and player ahead
    [
        decision: pass to player
    ]
]
```

Другой пример:

```text
for player in teammates 6, 7, 8
    order by distance to opposite_goal descending
[
    if player free
    [
        decision: pass to player
    ]
]
```

Переменная цикла в `order by` не пишется явно — критерий применяется к каждому перебираемому игроку. (Это требует осмысления - более сложные, чем просто distance, критерии могут быть невыразимы без переменной цикла)

## Ограничения

- Источником игроков в цикле может быть либо явный список (`teammates 6, 7, 8`), либо вся команда целиком (`teammates` — все партнёры, **исключая `me`**, или `opponents`). Индексация `list[i]`, вычисление длины и мутации списков по-прежнему запрещены.
- На уровне языка нет `nil`/`null`, нет `break`, нет функций высшего порядка.
- Вложенные циклы запрещены.

# Трансляция в Lua

- Базовый цикл транслируется в прямой `for _, _p in ipairs(...) do ... end` (по явному списку `{6, 7, 8}` или по `teammate_numbers()` / `opponent_numbers()` из `stdlib.lua`) либо в `for _p in each(...) do ... end`.
- Цикл с `order by` транслируется в предвычисление ключа сортировки (вместе с исходным индексом для стабильности при равенстве), `table.sort` и последующий `ipairs` с ранним `return`; для `order by distance to me ascending` по номерам партнёров есть готовый итератор `order_by_distance_asc(...)`.
- На переходном этапе (до появления транслятора DSL) в тактиках на Lua используются итераторы `each(...)` и `order_by_distance_asc(...)`; при необходимости цикл сопровождается комментарием о том, что он намеренно оформлен под дизайн будущего DSL.

# Открытые вопросы для дальнейшего обсуждения

- Точный синтаксис: `for player in teammates 6, 7, 8` / `for player in teammates` vs сохранение списка игроков в переменную.
- Какой набор критериев допустим в `order by` (только `distance to <цель>` или также другие метрики вроде ближайшего соперника / открытости).
- Поведение при необходимости включить `me` в обход (по умолчанию `teammates` исключает `me`, чтобы не отдать пас самому себе).
