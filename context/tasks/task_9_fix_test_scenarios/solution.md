# Решение по task_9: правки существующих сценариев для наблюдения

> Область: только существующие сценарии и существующие критерии остановки.
> Правки, зависящие от нового триггера `after_event` (task_10), здесь **не** учитываются.

## 1. Контекст и границы

Проблема `task_9`: replay в плеере идёт в реальном времени, поэтому «время наблюдения = модельное
время до остановки» (`SimulationControl::for_replay` ставит `rate = 1/fixed_dt`). В текущих
сценариях мяч находится вплотную к линии и летит с большой скоростью, из-за чего событие наступает
за 2–4 шага (~0.4 c), и визуально это выглядит как мгновенное завершение.

Решение в рамках этой задачи — **удлинить фазу до события** (отодвинуть мяч и/или уменьшить
скорость) и **уменьшить шаг симуляции** для плавности движения. Триггер остановки остаётся
прежним (`event`), поэтому мы наблюдаем сам момент события (уход мяча за линию / гол), а не
последующую расстановку — расстановку закроет `task_10` отдельным триггером `after_event`.

Ограничения физики, которые учитываются при выборе значений:

- поле: ширина `68.0 м`, длина `104.615 м`;
- створ ворот: `x ∈ [30.34, 37.66]` (ширина ворот `7.32 м`, центр `x = 34`);
- радиус мяча `0.11 м`;
- трение мяча `2.0 м/с²` (максимальный пробег свободного мяча `v0² / 4`);
- RNG сценария детерминирован (`temperature = 0.0`), поэтому удар всегда прямой со скоростью
  `shot_power / 5`.

## 2. Общие правки

Во всех сценариях:

1. `scenario.toml`: `dt = 0.1` → `dt = 0.05`.
2. Страховочный `steps = 1000` оставить без изменений: при `dt = 0.05` это 50 c модельного
   времени, а события наступают за ~3–4 c.
3. `expect.stop`, `[[expect.journal]]` и `final_state.toml` не меняются: они не привязаны к точному
   числу шагов и продолжают совпадать.

## 3. Правки по сценариям

### 3.1 `corner` — `initial_state.toml`

Мяч отодвинут от лицевой линии команды A (`z = 0`) и замедлен; `x = 10` оставлен вне створа ворот,
чтобы сработал `GoalLine`, а не гол.

```toml
stage = "Play"

[ball]
position = { x = 10.0, y = 0.0, z = 40.0 }
velocity = { x = 0.0, y = 0.0, z = -15.0 }
last_possessing_team = "A"
```

Итог: событие `GoalLine` ≈ 3.5 c (~70 шагов при `dt = 0.05`).

### 3.2 `goal_kick` — `initial_state.toml`

Геометрия та же, что у `corner`, но `last_possessing_team = "B"` — проверяется голкик, а не угловой.

```toml
stage = "Play"

[ball]
position = { x = 10.0, y = 0.0, z = 40.0 }
velocity = { x = 0.0, y = 0.0, z = -15.0 }
last_possessing_team = "B"
```

Итог: событие `GoalLine` ≈ 3.5 c (~70 шагов).

### 3.3 `throw_in` — `initial_state.toml`

Мяч отодвинут от правой боковой (`x = 68`) к левой; движение только по `x`.

```toml
stage = "Play"

[ball]
position = { x = 10.0, y = 0.0, z = 52.3 }
velocity = { x = 20.0, y = 0.0, z = 0.0 }
last_possessing_team = "A"
```

Итог: событие `Touchline` ≈ 3.5 c (~70 шагов).

### 3.4 `goal_into_b` — `initial_state.toml`

Мяч отодвинут от ворот B (`z = 104.615`), `x = 34` остаётся в створе ворот.

```toml
stage = "Play"

[ball]
position = { x = 34.0, y = 0.0, z = 70.0 }
velocity = { x = 0.0, y = 0.0, z = 15.0 }
last_possessing_team = "A"
```

Итог: событие `Goal` (в ворота B) ≈ 2.9 c (~58 шагов).

### 3.5 `goal_into_a` — `initial_state.toml`

Мяч отодвинут от ворот A (`z = 0`), `x = 34` остаётся в створе ворот.

```toml
stage = "Play"

[ball]
position = { x = 34.0, y = 0.0, z = 35.0 }
velocity = { x = 0.0, y = 0.0, z = -15.0 }
last_possessing_team = "B"
```

Итог: событие `Goal` (в ворота A) ≈ 2.9 c (~58 шагов).

### 3.6 `stdlib_kick_to_goal` — `initial_state.toml`

Здесь мяч не задаётся начальной скоростью, а получает её от удара (`kick_outcome`). Скорость удара
фиксирована: `shot_power = 50` → `10 м/с`, максимальный пробег `10² / 4 = 25 м`. Поэтому бьющего
нельзя отодвигать дальше ~25 м от ворот: иначе мяч не докатится и гол не состоится.

Текущее положение A#1 `z = 102` (≈2.6 м до ворот). Переносим его и мяч на `z = 82` (≈22.7 м до
ворот) — это даёт ~3.5 c полёта при достаточном запасе по дистанции.

```toml
stage = "Play"

[ball]
position = { x = 34.0, y = 0.0, z = 82.0 }
velocity = { x = 0.0, y = 0.0, z = 0.0 }
possessed_by = { team = "A", number = 1 }
last_possessing_team = "A"

[[players]]
team = "A"
number = 1
position = { x = 34.0, y = 0.0, z = 82.0 }

[[players]]
team = "B"
number = 1
position = { x = 34.0, y = 0.0, z = 10.0 }
```

Итог: `kick_outcome` на первом шаге, затем `Goal` в ворота B ≈ 3.5 c (~70 шагов).

## 5. Проверка

После правок прогнать:

```sh
cargo test -p ynwa-integration-testing
```

Все сценарии должны остаться зелёными (ожидания не привязаны к точному числу шагов). Для визуальной
проверки — запись сценария после прогона теста и replay:

```sh
./replay.sh ~/.ynwa/scenarios/<scenario>.jsonl
```

## 6. Что остаётся на `task_10`

Текущий триггер `event` останавливает прогон в момент события, поэтому финальный кадр показывает
мяч за линией, а не расстановку после стандартного положения (мяч на угловом/у ворот/на точке аута).
Чтобы наблюдать и расстановку, после реализации `task_10` эти же сценарии переключаются на
`when = "after_event"` с `delay_steps = 1..=2`, а в `final_state.toml` добавляется проверка
положения мяча/`restart_*`. В рамках текущей задачи это не делается.
