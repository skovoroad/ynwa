# Шаг 2: анализ требований и выработка архитектурного решения

Этот шаг выполняют ИИ-ассистент и человек. 
DOR: 
- выполнен DOD шага 1.
- git переключен на ветку задачи.
- начат НОВЫЙ диалог с ИИ-ассистентом

На этой стадии не пишется код, производится подготовка архитектурного решения для задачи.

Порядок работы:
- ИИ-ассистент читает файл context/context.md для ознакомления с проектом.
- ИИ-ассистент читает файл task.md из папки задачи.
- ИИ-ассистент читает дополнительную документацию, если это надо.
- Если на момент выполнения шага в папке задачи есть файла arch_review.md (замечания после ревью), следует добиться исправления этих замечаний и подтверждения от человека, что правки приняты. После этого файл arch_review.md  следует стереть (он остаётся в истории).
- Если на момент выполнения шага в папке задачи нет файла arch_review.md (замечания после ревью), то происходит уточнение текстовой постановки задачи. ИИ-ассистент проводит анализ, уточняет непонятные вопросы по постановке задачи у человека. Если вопросов нет, то проверяет, что задача реализуема, что постановка непротиворечива. ИИ-ассистент ищет альтернативные решения: можно ли упростить задачу, использовать архитектурные шаблоны. Описав результаты анализа, ИИ-ассистент добивается от человека подтверждения: нужно ли отредактировать постановку задачи. При необходимости поисходит несколько итераций редактирования, пока человек не подтвердит постановку задачи. После этого файл task.md в окончательном виде коммитится.
- Если на предыдущей стадии не были согласованы конкретные типы и программные интерфейсы, то по той же процедуре происходит их согласование.
- Итоговый файл коммитится.

DOD: архитектурное решение описано в файле task.md в папке задачи, согласовано и закоммичено в ветку задачи. Файл arch_review.md в папке задаче отсутствует.
